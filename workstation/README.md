# Восстановление окружения на Fedora

1. Установите Fedora x86_64, Git, Go 1.27, Make, GCC, Docker с Compose и VS Code. При использовании Flatpak установите сборку `com.visualstudio.code` из Flathub. Проверьте доступ к локальному Docker от своего пользователя.
2. Разместите `hibinka-app` и `kafka-lock-autoscaling` в соседних каталогах. Запустите `bash workstation/bootstrap-fedora.sh` из Hibinka51. Скрипт устанавливает uv, Python 3.11, Node 22, gopls, Delve, Helm, Terraform, OpenTofu, Ansible Core, Flux CLI и расширения из списка. Он использует существующие бинарники, если они уже доступны. Для восстановления инструментов Kubernetes восстановите Minikube и kubectl из официальных релизов с версиями, соответствующими локальному стенду. Проверенные версии здесь — Minikube 1.38.1, kubectl 1.35.4 со встроенным Kustomize 5.7.1 и Helm 3.22.1.
3. Добавьте `~/.local/bin` в PATH системного терминала. В Flatpak используйте профиль терминала хоста `flatpak-spawn --host zsh`. Откройте `workstation/Hibinka.code-workspace`. Он подключает Go, gopls и Delve через обёртки хоста в `~/.local/libexec/vscode-host`. Для Flatpak bootstrap настраивает пользовательский профиль. Резервная копия сохраняется рядом с `settings.json`.
4. Из корня Hibinka51 выполните `uv venv --python 3.11 .venv` для нового окружения, затем `uv pip install --python .venv/bin/python -r hibinka51-server/requirements.txt -r workstation/python-test-requirements.txt`. Установите зависимости клиента через `npm ci` в `hibinka51-client`. Команды запуска и настройки .env приведены в README проекта.
5. Выполните `workstation/check.sh`. Он проверяет локальные команды и не подключается к Kubernetes API. Для FastAPI используйте одноимённую задачу VS Code или `workstation/test-hibinka-server.sh`. Она тестирует снимок серверной части из HEAD со встроенной тестовой фикстурой SQLite в изолированном каталоге. Для Go запускайте тесты по пакетам всех шести модулей в `go.work`.
6. Настройте вход в GitHub Pull Requests и выберите доверенный SSH-хост при первом использовании. Для Kubernetes указывайте контекст подтверждённого локального стенда явно.

Для ручной работы с PostgreSQL доступен `psql` в образе `postgres:15-alpine`. Проверки Terraform и OpenTofu используйте в отдельных рабочих каталогах, особенно если они используют разные файлы состояния.
